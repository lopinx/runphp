# RunPHP —— 基于 FrankenPHP 的 PHP 建站环境管理软件 · 实施计划

## 一、产品定位

一个桌面 + 服务器两用的 PHP 建站环境管理器：内置 FrankenPHP 运行时的下载与生命周期管理，提供站点管理（域名 / HTTPS / Worker 模式 / 日志）、数据库管理（内置 SQLite 引擎 + 管理已有的 MySQL/MariaDB、PostgreSQL 实例）、hosts 文件管理。桌面端为 Tauri 2 原生窗口，无 UI 的 Linux 服务器以 CLI + 内建 Web 面板方式运行。

## 二、技术选型（已确认）

| 层 | 选型 | 说明 |
|---|---|---|
| 核心逻辑 | Rust（Cargo workspace 中的 `runphp-core` 库） | 桌面/CLI/Web 面板三端共用 |
| 桌面壳 | Tauri 2 | Windows（WebView2）+ Linux（webkit2gtk） |
| 前端 | Vue 3 + Vite + TypeScript + Naive UI + Pinia + vue-router | 一份构建产物，桌面壳与 Web 面板复用 |
| 无头模式 | clap CLI + axum 内建 Web 面板 | 同一个 Vue dist，REST API 与 Tauri command 一一对应 |
| SQLite | rusqlite（内置引擎） | 既是管理对象也用于应用自身元数据 |
| MySQL/PG 客户端 | sqlx（runtime-tokio，mysql + postgres feature） | 仅连接管理已有实例，不捆绑服务器 |
| 进程/异步 | tokio | FrankenPHP 子进程管理、日志流 |

关键事实（已调研）：FrankenPHP 最新版 v1.12.7，官方提供 Windows 二进制（`frankenphp-windows-x86_64.zip`，约 60MB，含 PHP 与扩展 dll）和 Linux 静态二进制（`frankenphp-linux-x86_64` / `-aarch64`，免依赖），满足"首次启动在线下载"方案。FrankenPHP 本质是 Caddy，配置走 Caddyfile，支持 admin API（默认 127.0.0.1:2019）热重载。

## 三、项目结构

```
runphp/
├── Cargo.toml                # workspace
├── crates/
│   ├── runphp-core/          # 全部业务逻辑（无 UI 依赖）
│   │   └── src/
│   │       ├── config.rs     # 应用状态模型与持久化（数据目录下 JSON）
│   │       ├── runtime.rs    # FrankenPHP 下载/校验/多版本管理
│   │       ├── caddy.rs      # Caddyfile 生成、进程启停、admin API 热重载
│   │       ├── site.rs       # 站点 CRUD
│   │       ├── hosts.rs      # hosts 解析/受管区块读写
│   │       ├── db/sqlite.rs  # SQLite 浏览/查询/导入导出
│   │       ├── db/remote.rs  # MySQL/PG 连接档案（sqlx）
│   │       └── logs.rs       # 日志文件、实时 tail
│   └── runphp-cli/           # 无头二进制：clap 子命令 + axum 面板服务
├── src-tauri/                # Tauri 2 壳，commands 薄封装 core
├── src/                      # Vue 3 前端（桌面与面板共用）
│   ├── views/{Dashboard,Sites,Databases,Hosts,Settings}.vue
│   ├── api/                  # 适配层：桌面走 invoke，面板走 fetch
│   └── stores/
└── docs/                     # 中文文档
```

数据目录：Windows `%APPDATA%\RunPHP`，Linux `~/.local/share/runphp`（可用 `--data-dir` 覆盖）。存放：下载的运行时分版本目录、生成的 Caddyfile、站点根目录默认位置、日志、元数据（一个 SQLite 文件 + JSON 配置）。

## 四、核心模块设计

### 4.1 运行时管理（runtime.rs）
- 启动时检测本地运行时；缺失则引导从 GitHub Releases 下载对应平台资产，校验 SHA256 后落地数据目录。
- 支持多版本并存（`runtimes/v1.12.7/frankenphp(.exe)`），站点可绑定版本，实现"多 PHP 环境"。
- Windows 包内含 php 扩展 dll：提供扩展开关 UI，通过生成/修改 php.ini（`extension=xxx.dll`）实现；Linux 静态构建扩展集固定，只读展示。
- 提供 `runphp runtime list/install/use` CLI。

### 4.2 站点管理（site.rs + caddy.rs）
- 站点模型：名称、域名列表、端口、根目录、HTTPS 开关、Worker 模式（入口脚本 + 进程数）、PHP ini 覆盖、绑定运行时版本。
- 每次变更后整体重新生成一份 Caddyfile（模板拼接，带注释头），形如：
  ```
  { frankenphp
    admin 127.0.0.1:2019 }
  mysite.test {
      root * /path/to/site
      encode gzip
      php_server { worker public/index.php 4 }   # worker 开启时
  }
  ```
- 生命周期：首次启动 spawn 子进程（stdout/stderr 重定向到日志文件）；运行中变更通过 Caddy admin API `POST /load` 或 `frankenphp reload --config` 热重载；停止走 admin API `/stop` + 兜底 kill。PID 记录于数据目录。
- 本地 HTTPS：使用 Caddy `tls internal` 自签本地 CA；提供"安装信任根证书"动作（Windows `certutil -addstore root`；Linux 提示需 root，复制命令或 pkexec）。
- 日志：每站点访问日志 + 全局错误日志；前端通过 Tauri event / 面板 SSE 实时 tail。
- 新建站点可选生成骨架（index.php 探针页）。

### 4.3 hosts 管理（hosts.rs）
- 解析系统 hosts（Win `C:\Windows\System32\drivers\etc\hosts`，Linux `/etc/hosts`），以成对标记注释维护受管区块：
  ```
  # >>> RunPHP 托管开始（勿手动编辑本区块）>>>
  127.0.0.1 mysite.test
  # <<< RunPHP 托管结束 <<<
  ```
- 写入前自动备份（`hosts.runphp.bak.<时间戳>`）。区块外内容只读不改。
- 权限策略：无权限时不硬写，而是展示待写入条目并提供：Windows 触发 UAC 提权重写；Linux 生成 `sudo` 命令供复制/pkexec。站点创建向导可一键"写入 hosts"。

### 4.4 数据库管理
- **SQLite（内置）**：列出数据目录下所有 .db/.sqlite 文件并支持新建；表/视图/索引结构浏览、行数据分页查看与编辑、SQL 编辑器（结果表格 + 错误提示）、导出 SQL dump / 导入。
- **MySQL/MariaDB、PostgreSQL（管理已有实例）**：连接档案（名称/host/端口/用户/密码/SSH 暂不做）；测试连接、列出库与表、SQL 编辑器、逻辑备份还原（优先探测本机 `mysqldump`/`pg_dump`，缺失时用 sqlx 逐表 SELECT 导出）。
- 不做：捆绑安装 MySQL/PG 服务器（明确边界，控制体量）。

### 4.5 无头 Linux 模式（runphp-cli）
- 子命令：`runphp start|stop|reload|status`、`runphp site add|list|edit|rm`、`runphp db ...`、`runphp hosts sync`、`runphp runtime install`、`runphp panel serve --port 9080 --token xxx`。
- `panel serve`：axum 托管 Vue dist + REST API（与 Tauri command 同名同参），简单 bearer token 鉴权（默认仅监听 127.0.0.1，可显式开 0.0.0.0）。
- `runphp service install` 生成 systemd unit（`ExecStart=runphp start --foreground`），一条命令上服务器常驻。
- 前端 `src/api/` 适配层按编译注入的运行模式自动切换 invoke / fetch，一套代码两处运行。

## 五、前端页面

- **仪表盘**：运行时状态（版本/进程/端口）、站点数量、快捷启动停止、最近日志。
- **站点**：列表（状态灯、域名、端口、操作）；新建/编辑向导（基本信息 → HTTPS → Worker → hosts 写入提示）；详情页日志 tab 实时滚动。
- **数据库**：左侧连接树（SQLite 文件 / MySQL / PG 档案），右侧结构浏览或 SQL 编辑器。
- **Hosts**：受管区块条目表格（增删改、一键同步站点域名）+ 系统 hosts 全文只读查看。
- **设置**：运行时版本管理（下载进度条）、数据目录、面板端口、PHP 扩展开关（Windows）。

## 六、实施里程碑

1. **M1 脚手架**：git init、Cargo workspace、Tauri 2 + Vue 3 + Naive UI 工程跑通空窗口与 `hello` command；中文 UI 骨架与路由。
2. **M2 运行时与首个站点**：runtime 下载/校验、Caddyfile 生成、进程启停；手工建一个站点跑通 `phpinfo`。
3. **M3 站点管理完善**：CRUD UI、热重载、日志实时查看、HTTPS + 证书信任、Worker 模式。
4. **M4 hosts 管理**：解析/受管区块/备份/提权流程，接入建站向导。
5. **M5 数据库管理**：SQLite 全套 → MySQL/PG 连接档案与 SQL 编辑器 → 备份还原。
6. **M6 无头模式**：runphp-cli 全部子命令 + axum 面板 + systemd 安装。
7. **M7 打包发布**：Windows NSIS/MSI、Linux deb/AppImage；中文 README 与用户文档。

每个里程碑独立可用；全程中文注释、文档与 commit 信息（约定式：`功能:`/`修复:`/`重构:` 等中文前缀）。

## 七、风险与对策

- **FrankenPHP Windows 支持较新**：M2 即验证 Windows 二进制可用性，若有坑优先保 Linux，Windows 侧降级为提示手动放置二进制。
- **hosts/证书需要管理员权限**：设计上"无权限不硬写"，永远提供可视化提示 + 可复制命令，避免静默失败。
- **GitHub 下载网络**：设置中支持自定义镜像/代理，下载失败给出清晰指引。
- **sqlx 编译体积/时间**：仅启用 mysql+postgres feature，release 用 lld 优化链接。

## 八、验证方式

- 每阶段用真实操作验收：M2 浏览器访问 `http://localhost:端口` 看到 phpinfo；M3 `.test` 域名 HTTPS 绿锁；M4 `ping mysite.test` 解析到 127.0.0.1；M5 在 UI 中建表插数据并用 sqlite3 CLI 复核；M6 在 WSL/服务器上纯 CLI 完成建站并用 curl 验证面板。
